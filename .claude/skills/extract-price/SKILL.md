# Извлечение цены товара

## Назначение

Получи данные **только по одной** карточке товара, URL которой передан пользователем. Не переходи к поиску других продавцов, похожих товаров, аксессуаров или вариантов товара, если пользователь не попросил об этом отдельно.

## Контракт

**Вход:** один абсолютный URL страницы товара (`http://` или `https://`).

**Выход:** строго один JSON-объект без Markdown, поясняющего текста и дополнительных полей:

```json
{"regular_price": null, "sale_price": null, "has_credit": false}
```

Значения:

- `regular_price` — число в рублях без символа валюты. Это зачёркнутая/старая цена до скидки. Если скидки нет, это текущая фактическая цена товара. Если установить цену надёжно не удалось — `null`.
- `sale_price` — число в рублях без символа валюты. Это текущая цена товара **при наличии явного снижения цены**; иначе `null`.
- `has_credit` — `true`, только если на странице товара есть явное предложение рассрочки или кредита для данного товара; иначе `false`.

Не добавляй в JSON комментарии, диапазоны, валюту строкой, дату, название товара, причины ошибок или оценочные значения.

## Алгоритм

### 1. Проверь URL

- Убедись, что пользователь передал ровно один абсолютный URL карточки товара.
- Трекинговые параметры (`utm_*`, `origin_referer`, `__rr`, `abt_att`, `sh`, `yclid`, `erid`) срезать вручную не нужно — скрипт делает это сам. Передавай URL как есть.
- Не меняй домен, идентификатор товара, регион, вариант товара, продавца или параметры, определяющие комплектацию.
- Если URL отсутствует, не является URL страницы товара или их несколько, запроси один корректный URL. До получения URL не выдавай объект с выдуманными данными.

### 2. Получи содержимое

**Начинай всегда с одного вызова** — из корня проекта, без `cd` и без промежуточных файлов:

```bash
node .claude/skills/extract-price/fetch-price.js "<url>"
```

Скрипт сам чистит URL, ходит по редиректам с cookie-jar и печатает сводку. Первое поле — `verdict`, он же определяет следующий шаг. Читай его, а не гадай по пустоте массивов.

| `verdict` | Что произошло | Что делать |
|---|---|---|
| `ok` | Найдены ценовые кандидаты | Работай со сводкой, §3-§6. Браузер — только если кандидаты противоречат друг другу или нужен `has_credit` (см. §6) |
| `empty` | HTTP 200, крупная страница, цены в HTML нет — SPA | Браузер, шаг 2b |
| `js_challenge` | Анти-бот заглушка вместо товара | Браузер, шаг 2b. Челлендж **не решать** самому |
| `blocked` | 401/403/429/503 от анти-бота | Браузер, шаг 2b. Защиту не обходить |
| `redirect_loop` | Петля редиректов даже с cookie-jar | Браузер, шаг 2b |
| `network_error` | Соединение не установилось | Браузер, шаг 2b |
| `http_error` | 404 и подобное | Цена не найдена, вернуть `null` |

Поля сводки при `verdict: ok`:

- `jsonld` — Offer/AggregateOffer из `application/ld+json`, самый надёжный источник;
- `microdata` — `itemprop=price` (в атрибуте `content` или в тексте узла);
- `stateBlocks` — объекты `"price":{...}` из состояния приложения (`current`/`old`/`discount`/`club`);
- `priceScalars` — скалярные поля вида `"price":23999`, `"oldPrice":…` — форма, которой нет в `stateBlocks`;
- `credit` — см. §6.

Не выгружай HTML целиком и не иди по цепочке `curl` → файл → несколько `grep`: каждый новый вызов с новым URL — отдельный запрос разрешения, и именно он, а не сеть, съедает время.

### 2b. Браузер

Открой ровно тот URL, который дал пользователь, дождись прогрузки карточки и выполни один готовый снимок вместо серии проб:

```js
(() => {
  const btn = [...document.querySelectorAll('button,a')]
    .find(e => /в корзин|добавить в корзин|купить/i.test(e.textContent) && e.textContent.length < 40);
  let box = btn;
  for (let i = 0; i < 8 && box && box.parentElement; i++) box = box.parentElement;
  const money = e => e.children.length === 0 && /\d[\d\s ]{2,}\s*₽/.test(e.textContent) && e.textContent.length < 45;
  const prices = [...document.querySelectorAll('*')].filter(money).map(e => {
    const s = getComputedStyle(e);
    return {
      txt: e.textContent.trim().replace(/\s+/g, ' '),
      strike: s.textDecorationLine.includes('line-through'),
      size: parseInt(s.fontSize),
      inBuyBox: box ? box.contains(e) : false,
    };
  }).slice(0, 20);
  const credit = [...document.querySelectorAll('*')]
    .filter(e => e.children.length === 0 && /рассрочк|кредит|частями|долям|сплит/i.test(e.textContent) && e.textContent.length < 110)
    .map(e => ({ txt: e.textContent.trim(), inBuyBox: box ? box.contains(e) : false }))
    .slice(0, 10);
  return JSON.stringify({ buyBox: box ? box.innerText.replace(/\s+/g, ' ').slice(0, 500) : null, prices, credit });
})()
```

`inBuyBox: true` — прямое доказательство принадлежности к основному блоку покупки; `strike: true` — старая цена; наибольший `size` внутри блока — текущая цена.

Если `prices` пуст, а `readyState` ещё `interactive` — подожди пару секунд и повтори. Если страница осталась заглушкой, капчей или требует авторизацию — не обходи защиту, считай цену ненайденной.

Не используй поисковую выдачу, сторонние агрегаторы, кешированные сниппеты и цену с другой страницы в качестве замены цены с переданного URL.

### 3. Найди цену именно товара

Ищи значения в порядке убывания надёжности:

1. Цена в основном блоке покупки выбранного товара, рядом с кнопкой «Купить», «В корзину» или селектором варианта (`inBuyBox: true`).
2. Поля Product/Offer в JSON-LD или структурированном состоянии страницы, соответствующие текущему SKU/варианту.
3. Явно помеченная старая/зачёркнутая цена и текущая цена в одном товарном блоке.
4. Видимый текст блока карточки товара, если он однозначно связан с основной покупкой.

Игнорируй:

- цены рекомендованных и похожих товаров, аксессуаров, страховок, сервисов, подписок и доставки;
- цену «от» (в том числе «Есть дешевле — от N ₽» — это другие продавцы), цену за месяц, кешбэк, бонусы, баллы, купоны, промокоды;
- цену другого цвета, объёма, комплектации, продавца или региона, если она не соответствует открытому варианту;
- цену комплекта/набора, если открыта карточка одиночного товара;
- MSRP/РРЦ, если она не показана как старая цена перед текущей скидочной ценой.

### 4. Определи `regular_price` и `sale_price`

- Если есть **явная** текущая цена и отдельная старая/зачёркнутая цена больше текущей, верни:
  - `regular_price` = старая цена;
  - `sale_price` = текущая цена.
- Если показана только одна фактическая цена товара либо старая цена не подтверждена, верни:
  - `regular_price` = текущая цена;
  - `sale_price` = `null`.
- `old: "0"`, `oldPrice: 0` и `discount.percent: 0` в состоянии страницы означают отсутствие скидки, а не нулевую цену. `sale_price` в этом случае — `null`.
- Не считай скидкой отличие «по карте», «по подписке», «с промокодом», «при оплате …», «войдите — цена станет ниже» или персональную цену. **Бери цену, доступную всем без условий.** Если магазин показывает две цены («с картой магазина» и «с другими банками»), `regular_price` — вторая, безусловная.
- Если найдены конфликтующие цены, предпочти цену в основном блоке выбранного товара и откажись от менее надёжных значений.

### 5. Нормализуй цену

- Принимай только денежные значения в российских рублях, явно помеченные `₽`, `руб.`, `рублей`, `RUB` либо расположенные в рублёвом ценовом блоке российского магазина.
- Удали неразрывные и обычные пробелы, символы валюты, слова валюты и прочие нецифровые символы-разделители: `16 690 ₽` → `16690`.
- Если цена содержит копейки, замени запятую на точку и верни число: `1 999,50 ₽` → `1999.5`. Хвост `.0000` из микроразметки отбрось: `16690.0000` → `16690`.
- Не округляй и не умножай цену. Не преобразовывай помесячный платёж в полную стоимость.
- Не возвращай цену строкой, например `"16690"` или `"16 690 ₽"`.

### 6. Определи рассрочку/кредит

Скрипт отдаёт `credit.verdict`:

| Значение | Смысл | Действие |
|---|---|---|
| `offer_found` | В теле страницы есть оффер: сумма/срок или кнопка оформления | Проверь цитаты в `credit.strong` и ставь `true`, если они относятся к этому товару |
| `noise_only` | Только шаблонные упоминания (SEO-текст, ссылка «Кредит и рассрочка») | **Не решай по HTML.** Это «не определено», а не «нет» |
| `none` | Упоминаний нет вовсе | `false` |

Важно: блок рассрочки почти всегда дорисовывается на клиенте, поэтому `noise_only` при HTML-разборе — обычное дело. Если по этому URL значение `has_credit` действительно нужно, посмотри блок покупки в браузере (§2b, поле `credit` с `inBuyBox: true`). Если проверять браузером не стали — верни `false` и не выдавай догадку за факт.

Ставь `true`, когда в блоке покупки есть явное предложение:

- «рассрочка», «в рассрочку», «кредит», «в кредит», «взять в кредит», «доступен в кредит»;
- «оплата частями», «плати частями», «долями», «Сплит» — это тоже рассрочка;
- «0-0-6», «0-0-12», «0%» с ясным указанием на рассрочку или кредит;
- помесячный платёж по этому товару: «от 941 ₽ в месяц», «2 700 ₽ × 10 месяцев», «сегодня 0 ₽, далее 10 платежей».

Не ставь `true` из-за: способов оплаты и логотипов банков; ссылок и пунктов меню «Кредит и рассрочка» (`/about/credit/`); SEO-текста в `<meta name="description">` и `og:description` («…купить в кредит или рассрочку»); рекламного баннера вне карточки; кредита для другого товара. Отложенный платёж без разбиения на части («оплатить позже до 30 октября») рассрочкой не считается.

### 7. Обработка отсутствующих данных

- Если цена не найдена или не может быть надёжно отнесена к товару, верни `regular_price: null` и `sale_price: null`.
- Если найдена только текущая цена, верни её в `regular_price`, а `sale_price: null`.
- Если рассрочка не найдена, заблокирована или неоднозначна, верни `has_credit: false`.
- Никогда не угадывай цену, не подставляй цену из поисковой выдачи и не выводи нули вместо неизвестных значений.

### 8. Известные сайты

Проверено 13.08.2026. Помогает выбрать маршрут заранее, но `verdict` всё равно главнее — защита меняется.

| Сайт | Маршрут | Особенности |
|---|---|---|
| `citilink.ru` | скрипт (`ok`) | Цена в JSON-LD и `priceScalars`. Рассрочка только на клиенте → для `has_credit` нужен браузер |
| `apple-market.ru` | скрипт (`ok`) | Цена в микроразметке с хвостом `.0000`. Кнопка «Взять в кредит» видна в HTML |
| `dns-shop.ru` | браузер (`blocked` 401) | Qrator. В браузере цена в JSON-LD; блок покупки грузится лениво |
| `ozon.ru` | браузер (`blocked` 403) | Две цены: «с банками» (по карте) и «с другими банками» — брать вторую. «от N ₽» = другие продавцы |
| `mvideo.ru` | браузер (`empty`) | Angular SPA. Цена в `.price__main-value`. «Войдите — цена станет ниже» игнорировать |
| `store77.net` | браузер (`js_challenge`) | Proof-of-work на JS. Рассрочка названа «Плати комфортно / оплата частями» |

## Проверка перед ответом

Перед выдачей результата проверь:

- В JSON ровно три ключа: `regular_price`, `sale_price`, `has_credit`.
- Цены — JSON-числа или `null`, без валюты и пробелов.
- `sale_price` не задана без доказанной скидки.
- При двух ценах `regular_price` больше `sale_price`.
- `has_credit` имеет тип boolean, не строку.
- Ответ является валидным JSON в одной строке.

## Примеры

**Вход**

```text
https://shop.example/product/airpods
```

На странице: текущая цена `16 690 ₽`, зачёркнутая цена `19 990 ₽`, блок «Рассрочка 0-0-12».

**Выход**

```json
{"regular_price":19990,"sale_price":16690,"has_credit":true}
```

Если на странице показано только `16 690 ₽`, а рассрочка не упомянута:

```json
{"regular_price":16690,"sale_price":null,"has_credit":false}
```

Если доступ заблокирован или цена не найдена:

```json
{"regular_price":null,"sale_price":null,"has_credit":false}
```
